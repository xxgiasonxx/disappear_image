# 平台設定

## 概述

目前網站只針對 **X (Twitter)** 產生圖片。棋盤格 PNG 的效果仰賴兩件事：

1. 平台**保留 PNG 的 Alpha 通道**，沒有把圖片轉成 JPEG
2. 平台產生縮圖時，會把相鄰的透明與不透明像素平均

只要平台把圖片重新編碼成 JPEG（Alpha 通道被丟掉、透明像素被填色），棋盤格效果就會失效。

---

## X (Twitter)

### 限制

X 平台對 PNG 有 **1MB 限制**，超過就會被再壓縮。本專案透過以下方式把輸出控制在 1MB 內：

1. **色彩量化**：使用 Median-cut 將顏色減少到 32 色或更少
2. **棋盤格化**：一半像素是完全相同的透明像素，PNG 壓縮效率大幅提升
3. **參數搜尋**：逐步減少顏色數或解析度直到符合大小限制（見 [演算法詳解](algorithm.md#3-參數搜尋優化解-vs-暴力解)）

### 輸出規格

| 項目 | 值 |
|------|----|
| 格式 | PNG（RGBA） |
| 檔案大小 | ≤ 1MB |
| 邊長 | 至少 1000px（過小的圖會先放大）；檔案太大時再縮小，優化解最低 scale 0.4、暴力解最低 0.3 |
| 顏色數 | 32 / 16 / 8 / 4 / 2 |

---

## 其他平台

Discord、LINE 等平台也會產生縮圖，但各自的再壓縮規則（是否保留透明度、檔案大小上限）不同，目前尚未針對它們調整參數。要支援新平台時，需要確認：

- 上傳 PNG 後是否保留 Alpha 通道
- 觸發再壓縮的檔案大小上限，並調整 `src/lib/xProcessor.ts` 中的 `MAX_SIZE`
- 縮圖預覽的背景色（影響縮圖被沖淡後的顏色）
